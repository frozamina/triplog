# 覆盖升级验证

发布任何新版本前，必须用真实旧版用户数据库验证迁移。以下是真机待执行检查，不代表已经通过。

1. 安装旧版本 APK，创建跨日、多段、等待、免费段、待补花费、模板和自定义标签。
2. 开始实时打卡，记下开始时间；强制停止 App，重开并检查继续计时；重启手机再检查。
3. 导出 JSON 至手机可找回的文件夹，再导出 CSV、PNG，确认文件可打开。
4. 使用同一签名、同一包名、较高 versionCode 构建新版，直接安装覆盖，不能卸载旧版。
5. 检查全部记录数量、ID、起止时间、金额、备注、模板和正在计时的段与旧版一致。
6. 若更改 schema，分别从每一个已发布旧 schema 迁移到最新版，检查逐字段保留，并验证迁移中断回滚。
7. 导入已导出备份，确认相同 ID 不重复、其他本机记录不被删除；导入损坏备份应失败且不改变原数据。
8. 分别在 Android 8 与 Android 15/16 手机检查状态栏遮挡、键盘弹起、系统返回、文件选择器、长中文标题。

## 当前迁移

schema 1：trips / templates，每个记录以 JSON 保存，Leg 与 Transfer 为两个独立数组。

schema 2：新增 revisions 表，保存旧 trip/template 的完整 JSON；不改动 trips / templates 的任何行。

后续字段优先使用可选 JSON 字段，读取时提供默认值。如需要更改 SQL 表结构，必须新增并测试相应 onUpgrade 步骤；不能修改已经发布过的迁移。
